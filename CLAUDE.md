# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A World of Warcraft: The Burning Crusade Classic DPS simulator. A Go simulation engine
(`sim/`) and a TypeScript web UI (`ui/`) that talk to each other over protobuf messages
defined in `proto/`. Deployed at https://wowsims.com/tbc.

## Commands

The makefile is the build system; npm scripts are thin wrappers around it. Requires Go >= 1.25,
`protoc` + `protoc-gen-go`, and Node >= 22.

```sh
make setup                # one-time: install gofmt pre-commit hook and `air` (file watcher)
npm start                 # == WATCH=1 make devmode; the normal dev loop (see below)
make host                 # full client build, serve at http://localhost:8080/tbc/$CLASS/$SPEC/
make test                 # all Go tests
make update-tests         # promote *.results.tmp -> *.results after intended result changes
make proto                # regenerate Go + TS protobuf code
make clean                # nuke generated code, dist/, node_modules
```

Dev-loop variants, fastest to slowest feedback:

| Command | What it gives you |
| --- | --- |
| `WATCH=1 make devmode` | Go server on :3333 + `vite serve` (:5173) with HMR. Sub-second TS reloads, Go rebuilds on change. Use this by default. |
| `WATCH=1 make rundevserver` | Go server on :3333 serving `dist/`, `vite build --watch`. Best when iterating on core Go sim code. |
| `WATCH=1 make host` | Full rebuild + `http-server` on :8080. Slowest; closest to production. |
| `make host_$spec` | Rebuild only, then serve. |
| `make webworkers` | Rebuild just `ui/worker/*` (they are built separately — see below). |

Lint / format / typecheck (all TS-side; Go uses `gofmt`, run by the pre-commit hook or `make fmt`):

```sh
npm run type-check        # tsc --noEmit
npm run lint              # oxlint (ui/) + stylelint (ui/**/*.scss)
npm run format            # lint --fix then oxfmt
npm run test:locales      # validate assets/locales/**/*.json against schemas/
```

Note the toolchain: **oxlint/oxfmt, not eslint/prettier**; stylelint with a BEM plugin for SCSS.
Style is tabs, width 4, print width 160, single quotes, trailing commas (`.oxfmtrc.json`).

### Running a single Go test

Go tests need generated protobuf and an embed stub before they'll build:

```sh
make sim/core/proto/api.pb.go binary_dist/dist.go        # once, what CI does
GOARCH=amd64 go test --tags=with_db ./sim/shaman/elemental/ -run TestElemental
```

`--tags=with_db` is required (it pulls in the item database). `GOARCH=amd64` matters —
results are float-sensitive and the checked-in golden files were generated on amd64.
`make test` sets both and additionally builds `lib.wasm` first.

## Architecture

### The proto boundary

`proto/*.proto` is the single source of truth for everything crossing the Go/TS line: sim
requests and results (`api.proto`), the rotation language (`apl.proto`), shared enums like
`Spec`/`Class`/`Stat` (`common.proto`), and per-class option messages (`shaman.proto`, …).

Generated output — **never edit these, they are gitignored/regenerated**:

- `sim/core/proto/*.pb.go`
- `ui/core/proto/*.ts`
- `ui/core/index.ts` (a barrel of every file under `ui/core`, generated by a makefile `awk` rule)

Both are rebuilt by `make proto`, and automatically as makefile dependencies of any build.

**Breaking proto changes are gated.** `TestProtoVersioning` (`sim/core/proto_test.go`) shells
out to `npx buf breaking` against remote master and compares `GetCurrentProtoVersion()` to
`.deployedprotoversion`. If you make a breaking change you must bump `current_version_number`
on the `ProtoVersion` message in `proto/common.proto`. This test needs `node_modules` and
network access.

### Go simulation engine (`sim/`)

- `sim/core/` — the engine. Event loop in `Simulation.RunOnce` (`sim.go`); `api.go` implements
  the proto request/response entry points; `agent.go` is the interface a spec implements;
  `character.go` holds stats/gear/cooldowns common to any character. Spells and auras are
  declarative configs: `unit.RegisterSpell(SpellConfig{...})`, `unit.RegisterAura(Aura{...})`.
- `sim/core/apl*.go` — the APL (Action Priority List) rotation interpreter. Rotations are
  data (`*.apl.json`), not code; `apl_action*.go` are the actions and `apl_value*.go` the
  conditions.
- `sim/$class/[$spec/]` — per-spec implementations. Every spec must be registered in
  `RegisterAll()` in `sim/register_all.go`.
- `sim/common/` — shared item/enchant/consumable effects, split `classic/` vs `tbc/`.

The engine compiles four ways:

- **wasm** — `sim/wasm/main.go` → `dist/tbc/lib.wasm`, exposes functions on `globalThis`.
- **web server** — `sim/web/main.go` → `wowsimtbc` binary with the client embedded from
  `binary_dist/`. `--usefs` serves `dist/` from disk instead; `--wasm` (only valid with
  `--usefs`) makes the client sim in wasm rather than calling back to the server.
- **CLI** — `cmd/wowsimcli/`.
- **c-shared lib** — `sim/lib/library.go` (`make locallib` / `nixlib` / `winlib`).

### TypeScript UI (`ui/`)

- `ui/core/` — everything shared. `individual_sim_ui.tsx` is the base class every spec's UI
  extends; `sim.ts`/`raid.ts`/`player.tsx` are the settings model; `typed_event.ts` is the
  event/reactivity primitive the whole UI is built on; `proto_utils/` wraps raw proto types
  in usable classes (`Gear`, `Stats`, `Database`, `SimResult`).
- `ui/$class/$spec/` — a spec UI is four files: `index.ts` (entry point, instantiates
  `Sim` + `Player` + the UI class), `sim.ts` (a `registerSpecConfig(Spec.X, {...})` block
  declaring EP stats, display stats, defaults, and inputs), `presets.ts`, `inputs.ts`.
  Gear sets and rotations live alongside as `gear_sets/*.gear.json` and `apls/*.apl.json`.
- `ui/worker/` — sims run off the main thread. `sim_worker.ts` (wasm), `local_worker.ts`,
  `net_worker.ts` (delegates to the Go server), `reforge_worker.ts` (HiGHS LP solver for
  reforge optimization). **These are built by `vite.build-workers.mts`, separately from the
  main `vite build`**, and must be self-contained single files. Changing them requires
  `make webworkers`.
- `ui/scss/` — `core/`, `shared/`, and `sims/$class/$spec/index.scss` per spec.
- `ui/i18n/` + `assets/locales/` — i18next. Strings go in `en/translation.json` first; use
  `i18n.t('group.subgroup.key')`. Keys are validated in CI against `schemas/`.

**Sim pages are not real files.** There is no per-spec `index.html` and no makefile rule for
one. `tools/vite/spec_pages.mts` generates `/tbc/$CLASS/$SPEC/` from `ui/index_template.html`
in both `vite build` and the dev server. A directory becomes a page as soon as it has both
`ui/$CLASS/$SPEC/index.ts` and `ui/scss/sims/$CLASS/$SPEC/index.scss`. (`ui/index.html` *is*
real — it's the landing page.)

**JSX is vanilla DOM, not React.** `tsx-vanilla` with an `element`/`fragment` pragma that
vite injects into every module (`oxc.jsxInject` in `vite.config.mts`, mirrored for tsc by
`ui/types/jsx-inject.d.ts`). So: do not import `element`/`fragment`; do import `ref` from
`tsx-vanilla` when you need an element reference. JSX expressions evaluate to real DOM
`Element`s, so you can `.appendChild()` them directly.

### Tests are golden files

Spec tests call `core.RunTestSuite` with a `FullCharacterTestSuiteGenerator`, which sweeps
races / gear sets / talents / rotations and writes DPS, TPS, and stat weights into a checked-in
`sim/**/Test$Name.results` file (prototext, 5 decimal places to avoid cross-platform float
flake). On mismatch the run writes `*.results.tmp`; inspect the diff, and if the change is
intended run `make update-tests` to promote it.

The generator reads its fixtures **out of the UI tree** — e.g.
`core.GetGearSet("../../../ui/shaman/elemental/gear_sets", "p1_a")` and
`core.GetAplRotation("../../../ui/shaman/elemental/apls", "default")`. Editing a
`.gear.json` or `.apl.json` preset therefore changes sim test results.

CI (`.github/workflows/run_tests.yml`) shards `go list ./sim/...` four ways plus a separate
UI build job.

## Adding a new spec

Summarised from `docs/adding_sim.md`:

1. Add the `Spec` enum value in `proto/common.proto` (the name is used for templating), a
   class proto message if needed, and wire it into `PlayerOptions.spec` in `proto/api.proto`.
2. Add boilerplate for the spec in `ui/core/proto_utils/utils.ts`, then create
   `ui/$class/$spec/` (copy an existing spec) and `ui/scss/sims/$class/$spec/index.scss`.
   No HTML or makefile changes needed.
3. Implement `sim/$class/$spec/`, register it in `RegisterAll()` (`sim/register_all.go`),
   and add a `_test.go` following an existing spec's.
4. To launch it publicly, add it to `ui/core/launched_sims.tsx` and `ui/index.html`.

## Item database

`assets/database/db.bin`/`db.json` are generated from a local WoW client install via
`make db` (settings in `tools/database/generator-settings.json`, `make ptrdb` for PTR).
Requires `tools/database/wowsims.db`, which is gitignored. Most work does not need this —
only regenerate when working on the extraction tooling under `tools/database/` or `tools/db2tool/`.

## Deployment

Pushing to `master` runs tests, builds, and deploys via `.github/workflows/deploy.yml`, which
also writes `sim/core/TestProtoVersioning.results` back into `.deployedprotoversion`.
